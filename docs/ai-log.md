# Журнал взаємодії із ШІ

**Інструмент:** Claude (Anthropic), режим агента з доступом до файлів і терміналу.
**Підхід:** ШІ генерує код і тести, розробник формулює вимоги, перевіряє результат у браузері й тестами та приймає рішення.

## 1. Початковий промпт

> Ось завдання ЛР № 5 і архів сайту з ЛР № 4 (магазин THESTRONGEST: 38 HTML-сторінок, кошик у localStorage, фільтри каталогу, форми з валідацією, адмін-форма без збереження).
>
> Перетвори сайт на вебзастосунок «клієнт – сервер – база даних»:
> - **Сервер:** Node.js + Express, віддає статичні файли з `public/` і REST API під `/api`, формат JSON, коректні HTTP-коди.
> - **База:** SQLite. Таблиці: `products`, `product_images`, `reviews`, `orders`, `order_items`. Засіяти 30 товарами, взятими з поточних HTML-сторінок.
> - **API:** повний CRUD для товарів (адмін), створення/читання відгуків, створення замовлення (покупець) і читання/зміна статусу/видалення замовлень (адмін), список відділень НП.
> - **Клієнт:** не переписувати дизайн; каталог, картки товарів, кошик, оформлення й адмінку перевести на `fetch` + `async/await` з обробкою помилок. Якщо API недоступне – каталог показує статичні картки.
> - **Безпека:** серверна валідація, параметризовані запити, сума замовлення рахується на сервері, токен адміністратора у змінній середовища, заголовки безпеки, rate limit.
> - **Перевірка:** автотести API, наскрізна перевірка в браузері, розгортання на Render.

## 3. Виявлені ризики ШІ-згенерованого коду

- Код, що «виглядає правильно», але падає на конкретній бібліотеці (зайві параметри в `node:sqlite`) — виявлено ручними запитами.
- Взаємний вплив механізмів (rate limit ламав інші тести) — виявлено автотестами.
- Візуальні дефекти (кнопки, мобільна верстка) — виявлено лише переглядом скріншотів.
- Довіра до клієнта: ціна в кошику могла бути підмінена — сервер ігнорує ціну з запиту (є окремий тест).
